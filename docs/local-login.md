# Local account login

Accounts are linked to Telegram user IDs. Sending `/start` creates an account if needed and sends a login link through the bot. To sign in to a local instance, simulate this webhook request against the local backend and use the resulting token on the local login page.

## Prerequisites

- Start the local backend with its database configured. The `http` launch profile uses `http://localhost:5057` (`dotnet run --launch-profile http`).
- Configure `Telegram:BotToken` for your bot and `Telegram:WebhookSecret` for webhook validation in the local configuration.
- Send `/start` to that bot from your Telegram account so it can send you a reply.
- Ensure the local backend can reach the Telegram API.

## Send the local webhook request

Use an HTTP client such as Postman to send:

```http
POST http://localhost:5057/api/v1.0/telegram/webhook
Content-Type: application/json
X-Telegram-Bot-Api-Secret-Token: <your local Telegram:WebhookSecret>
```

Use the following JSON body. `123456789` is a fictional placeholder: replace both `message.from.id` and `message.chat.id` with your own Telegram user ID before sending. IDs must be JSON numbers, not strings. The update ID, message ID, date, and first name are example values.

```json
{
  "update_id": 100000001,
  "message": {
    "message_id": 1,
    "from": {
      "id": 123456789,
      "is_bot": false,
      "first_name": "Local"
    },
    "chat": {
      "id": 123456789,
      "first_name": "Local",
      "type": "private"
    },
    "date": 1792195200,
    "text": "/start",
    "entities": [
      {
        "offset": 0,
        "length": 6,
        "type": "bot_command"
      }
    ]
  }
}
```

## Open the local login page

1. Find the new message sent by the bot in response to the local request and copy the URL from its **Login** button. The webhook response itself does not contain the token.
2. The backend builds that URL as `https://{Host:Dns}/login/?token=...`. Replace its scheme, host, and port with your local application's address, preserving the path and token:

   ```text
   http://localhost:5057/login/?token=<token from the bot's new login link>
   ```

3. Open the resulting URL in your browser within five minutes of sending the local webhook request. The login page stores the token, loads the account, and redirects to `/`.

Use the token generated by the local instance: a token generated by another instance will not work unless it uses the same session database. If the token expires, repeat the local webhook request to receive a new link.

## Troubleshooting

- **HTTP 401:** the secret header does not match the local `Telegram:WebhookSecret` value.
- **HTTP 200 but no Telegram message:** check the backend logs, bot token, Telegram user ID, database connection, and Telegram API connectivity. The webhook can return HTTP 200 even when processing or message delivery fails.
- **The link opens another instance:** replace the URL origin with the local address as described above.
- **Login fails:** confirm that the token came from the latest local webhook request and has not expired.
